C. elegans · neural activity & behavior forecasting

Methods

Time-aware segmentation, forecast targets, population-level neural features, and the purge-gapped blocked / forward-chaining evaluation protocol.

Time-aware segmentation

Done & verified

Recordings are not sampled on a perfectly uniform time grid: 18 of 80 recordings contain exactly one real-time discontinuity (a pause), in every case splitting the recording roughly in half. Segmentation uses each recording's own actual timestamps, not frame-index counts: a gap larger than 3× a recording's own median inter-frame interval starts a new segment. All windows, splits, and purge gaps are built from only the largest contiguous segment per recording.

112,251 of 126,351 total frames were kept; 14,100 were discarded (11.2%).

Forecast targets and horizon

Done & verified

Forecast horizon: 5 seconds (≈8 frames, computed per recording from its own sampling interval — median ≈0.6s/frame across recordings). History window: 10 seconds of trailing behavior/neural features. Inputs at time t use only data with timestamp ≤ t — this is a genuine forecast, never same-time decoding.

Velocity target: velocity(t+h), continuous regression. Reversal-onset target: binary — 1 if a reversal begins strictly within (t, t+h], else 0 (derived from the reversal-state channel).

Features — population-level only

Done & verified

Behavior-history features: current velocity/angular-velocity/reversal state plus their trailing-window mean, spread, and net change. Neural features are population-level — overall activity mean/variance plus per-recording PCA components fit on the training fold only — never tied to a specific neuron index, since no verified identity mapping links ROI indices across recordings (see Data).

Models compared

Done & verified

Four conditions per task: persistence (carries forward the current value/state, no fitting), behavior-history-only, neural-population-only, and combined (both feature blocks). Velocity uses ridge regression; reversal-onset uses logistic regression. All scaling and PCA are fit on the training fold only and applied, never refit, to the held-out fold.

Evaluation protocol — two schemes, purge-gapped

Done & verified

Unit of analysis: the recording (80 of them), not frame, not animal. Within each recording's largest segment: 5 contiguous time-blocks, each held out once.

Purge gap: 15 seconds (10s history + 5s horizon) excluded from training on both sides of every test block, so no input/target window crosses a train/test boundary.

Primary scheme — blocked out-of-sample prediction: training may include blocks chronologically after a given test block. This is the main reported protocol.

Secondary scheme — forward-chaining: training restricted to data strictly before the test block (fully prospective; the first block is skipped, since it has no prior data). Reported alongside the primary scheme throughout Results, not instead of it.

Both schemes are pre-specified before this analysis was run — "pre-specified before outcome analysis," not formally pre-registered.

Reversal-onset metrics — rare-event aware

Done & verified

Reversal onset is a minority class (median prevalence ≈0.18–0.20 across recordings). PR-AUC and ROC-AUC are both reported alongside the recording's own prevalence rate as the reference baseline — not AUROC alone. Any fold with zero positive or zero negative test labels is excluded and counted, never scored as PR-AUC = 0. Exactly one such fold was excluded in each recording group (see Results for the exact count).

Marker-free / marker-present policy

Done & verified

The 43 marker-free recordings are the primary analysis. The 37 marker-present recordings run through the identical pipeline as a separate sensitivity analysis, reported side-by-side but never pooled into the primary numbers.
